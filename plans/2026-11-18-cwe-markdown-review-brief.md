# Review brief: CWE as markdown, and CWE 4.20, 4.21 and 5.0

## What this is

MITRE's Common Weakness Enumeration (CWE) is rendered as markdown for people and AI pipelines. Each edition gets an index, one page per weakness, one per category (4.x) or grouping (5.0), and one per view. The pages are generated by three standard-library Python modules from MITRE's versioned XML. Editions: 4.19.1 (existing), and new 4.20, 4.21 and 5.0. The 5.0 per-view CSV/JSON data merged separately in #162. The work was planned and built by AI agents (one implementer and one independent reviewer per task, then a whole-branch review); Kurt set the goals and made the scope decisions.

## Known limits and deliberate choices

- **Upstream errors are reproduced as published.** 5.0 and 4.21 CWE-1475: the observed example labelled CVE-2025-50328 links to CVE-2026-58052, as in MITRE's XML and site.
- **Content history:** omitted from the markdown; kept in the mirrored per-view JSON as MITRE publishes it, under Kurt's MITRE rule (recorded on #160). Kurt can ask for it to be stripped from the JSON.
- **4.20 and 4.21 are XML-only editions:** MITRE's archive has no per-view CSV or JSON for past releases.
- **Not on pages:** reverse relationships (children, member-of) and in-page outline anchors (#164).
- **Multi-paragraph code examples** (9 in 5.0) are fenced with single newlines between paragraphs (#163).
- **CI does not regenerate or check the markdown**; that needs the zips in CI (#158).
- **`INDEX.md` counts git-ignored originals** present in the checkout (a clean clone shows one fewer file for some CWE editions); pre-existing behaviour, #158.

**Update 2026-11-19.** Kurt: *"lets default to mirroring data faithfully, so that means leaving names in."* He then chose to include MITRE's content history in the markdown (#166). Claim 9 and the content-history items above describe the state merged in #161, before that change.

## Where the author is least confident

1. **Implicit-view predicates** are hand-written per filter string. They matched an XPath engine on all four editions, but a future MITRE filter string falls back to "members not computed" with a warning, not a failure.
2. **Markdown escaping** is tuned to GitHub's renderer. Other renderers (e.g. pandoc with math) may read `$…$` in three entries as math.
3. **The no-bulk-mirror interplay.** AGENTS.md now says the CWE markdown is committed by Kurt's decision while the XML stays in S3; the committed 4.19.1 and 5.0 CSV/JSON predate that sentence and are not explained by it.
4. **YAML front matter** quoting is safe for all current values but not hardened against values like `Yes`/`No` (#163).

## What to assess and how to report

Correctness of the rendering against MITRE's XML; honesty of every statement in metadata, README, AGENTS.md and the spec; privacy (content history); reproducibility; fitness for AI ingestion (one page as a self-contained, attributed unit). Report each finding as: severity (blocker / should-fix / minor), location (file:line or page path), concrete failure scenario, suggested fix, and whether you verified it by running something.
