# Review brief: CCM 4.1.1 and the CAIQ 4.1.0 regeneration

## What this is

CSA shipped Cloud Controls Matrix **4.1.1** inside its unchanged "CCM v4.1"
download bundle, and regenerated the CAIQ 4.1.0 questionnaire with 26 changed
question texts without changing its version label. This work adds 4.1.1 to the
dataset, replaces the CAIQ 4.1.0 extraction in place, and first gives CCM
version nodes in the SecID registry so that "4.1" can be told apart from
"4.1.0" and "4.1.1".

**State:** three open PRs, none merged. **Merge order: C, then A, then B.**

C exists because of A. One SecID-Service test asserts that an unversioned `ccm#A&A-01` is `found`, and registry deploys run the test suite before uploading. Merging A without C would stop every registry deploy.

## Known limits and deliberate choices

- **Unversioned `ccm#X` now demands a version.** This is the R1 interim behaviour AICM already has. SecID-Service resolves version nodes only for `version_required` sources.
- **`4.1` is a moving pointer.** It is a second instance of ADR-015's exception, against the first amendment's "a second case should build `version_tracks`". This is Kurt's decision, recorded.
- **The CAIQ 4.1.0 extraction was replaced in place.** The January text stays reachable at `74ff4b8` and in S3.
- **Workbook cell counts** (6,751 differing cells) are not machine-checked, because the workbooks are gitignored.
- **The `Introduction`, `Acknowledgments` and `Change Log` sheets are not extracted.** The ATT&CK disclaimer is quoted in the docs instead.
- **License:** the workbook's own notice says "may not be modified … may not be redistributed". It is quoted in `license.notes`, and the license fields are left unchanged for Kurt to decide. The same notice is in 4.1.0, which is already published here.
- **Deferred review minors** (also filed as an issue):
  - M1: the "wording" label includes apostrophe, hyphen and case edits;
  - M5: the root README's CAIQ `4.1` row has no SecID alias behind it;
  - M6: DORA `A13.3` lists `SEF-04` twice in CSA's cell;
  - M7: `parse_caiq.py --expect-ccm-version 4.1.0` without `--ccm-json` embeds 4.1.1 controls;
  - M8: one issue id reads as a verdict;
  - M9: absolute local paths in the committed plan.
- **Out of scope, filed as issues:** the AICM `1.1` alias disagreement between this repo and SecID; off-vocabulary or stale `desired_end_state` values; `ccm-caiq` 3.1 domain codes missing from SecID patterns (noted in PR A).

## Where the author is least confident

1. **The SecID resolver behaviour is untested against SecID-Service.** The registry passes every gate, but no local resolver run was done; claim 15 is checkable only after deploy.
2. **The meaning claims for IAM-13 and DCS-11.1.** "At least privileged user" → "a least-privileged user" is described as possibly changing who the MFA requirement covers. DCS-11.1 is described as asking about one location instead of two. Both are readings of English, not facts about intent.
3. **The punctuation-only versus wording split.** It is a mechanical definition (strip `[\s,;.]`, fold case). A curly-to-straight apostrophe counts as "wording", which is conservative.
4. **Whether replacing the CAIQ in place is discoverable enough** for someone who pinned to the January text.
