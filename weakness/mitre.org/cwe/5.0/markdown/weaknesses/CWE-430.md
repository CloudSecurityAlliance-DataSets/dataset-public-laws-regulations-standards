# CWE-430: Deployment of Wrong Handler

## Description

The wrong "handler" is assigned to process an object or request.

## Modes Of Introduction

- **Implementation**: This can happen when the product automatically "determines" the type of the object even if it is contradictory to an explicitly specified type.

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Integrity<br>Other | Varies by Context<br>Unexpected State | An example of deploying the wrong handler would be calling a servlet to reveal source code of a .JSP file, or |

## Potential Mitigations

- **Phase:** Architecture and Design

  Perform a type check before interpreting an object.

- **Phase:** Architecture and Design

  Reject any inconsistent types, such as a file with a .GIF extension that appears to consist of PHP code.

## Observed Examples

| Reference | Description |
| --- | --- |
| [CVE-2001-0004](https://www.cve.org/CVERecord?id=CVE-2001-0004) | Source code disclosure via manipulated file extension that causes parsing by wrong DLL. |
| [CVE-2002-0025](https://www.cve.org/CVERecord?id=CVE-2002-0025) | Web browser does not properly handle the Content-Type header field, causing a different application to process the document. |
| [CVE-2000-1052](https://www.cve.org/CVERecord?id=CVE-2000-1052) | Source code disclosure by directly invoking a servlet. |
| [CVE-2002-1742](https://www.cve.org/CVERecord?id=CVE-2002-1742) | Arbitrary Perl functions can be loaded by calling a non-existent function that activates a handler. |
