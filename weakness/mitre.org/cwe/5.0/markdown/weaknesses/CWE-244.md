# CWE-244: Improper Clearing of Heap Memory Before Release

## Description

The product uses realloc() to resize buffers that contain sensitive information.

## Alternate Terms

- **Heap Inspection** (Common-Name, Attack-Focused)

## Background Details

The realloc() function is commonly used to increase the size of a block of allocated memory. This operation often requires copying the contents of the old memory block into a new and larger block.

## Modes Of Introduction

- **Implementation**

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Confidentiality<br>Other | Read Memory<br>Other | Since realloc() leaves the contents of the original block intact but inaccessible to the program, this the program from being able to scrub sensitive data from memory. When sensitive data such as a password or an encryption key is not removed from memory, an attacker could use "heap inspection" to read the sensitive data using memory dumps or other methods. |

## Demonstrative Examples

### Example 1 (DX-148)

The following code calls realloc() on a buffer containing sensitive data:

*Example (Bad, C):*

```c
cleartext_buffer = get_secret();...
cleartext_buffer = realloc(cleartext_buffer, 1024);
...
scrub_memory(cleartext_buffer, 1024);
```

There is an attempt to scrub the sensitive data from memory, but realloc() is used, so it could return a pointer to a different part of memory. The memory that was originally allocated for cleartext_buffer could still contain an uncleared copy of the data.
