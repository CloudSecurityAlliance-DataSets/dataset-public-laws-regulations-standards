# CWE-1474: Non-Equivalent Data Transformation

## Description

The product parses or transforms data into another format, structure, or representation, but the newly-produced data is not semantically equivalent to the original data.

## Detection Methods

- **Method:** Manual Analysis

  Examine inputs that will be saved or otherwise processed, then look at how they are produced in output. Analyze outputs that are expected to be (1) unchanged from the inputs, or (2) changed in a controlled way. Consider analyzing the data to extract key elements, such as e-mail addresses or domain names, to ensure that they are consistent with the original input.

  **Effectiveness:** Moderate

  **Effectiveness Notes:** These methods could have mixed results depending on how the product receives the data, transforms it, and outputs the data. It might require domain-specific knowledge of the product's intended behavior in order to determine if some transformations were correct. These methods could be time-consuming and not necessarily complete, but there might not be well-established and well-understood methods for some subtypes of this weakness.

## Potential Mitigations

- **Phase:** Architecture and Design; Implementation

  Validate the transformed data against what was expected to be produced. If the data is complex and free-form with some "special elements" in them, consider re-parsing the output to ensure that it matches expectations.

## Demonstrative Examples

### Example 1

Consider a product that uses an automated language translation service that is used to translate vendor-controlled web pages that are used for technical support. Consider that these web pages include domain names and email addresses for users to access.

*Example (Bad, Algorithm):*

```algorithm
The product invokes the translation service
on the entire message text without any special
treatment or consideration for contact information
such as email addresses and domain.
```

If the translation is from English to Polish, then "example.com" might be translated to "przyklad.com" - a different web site entirely. Alternately, an email address such as "address@example.com" could be translated to "adres@przyklad.com". If an attacker can control the domain or email address that is generated by the translation, then the attacker might be able to spoof communications with the product's users.

*Example (Good, Algorithm):*

```algorithm
The code could be changed to mark which words
or phrase should not be translated. Alternately, the
original web pages could be structured in a way that
uses templates that insert non-translatable data such
as email addresses. A third option could be to analyze
the resulting output and compare expected data
elements against an allowlist of known-valid
values.
```
