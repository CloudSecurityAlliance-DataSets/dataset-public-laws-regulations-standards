# CWE-836: Use of Password Hash Instead of Password for Authentication

## Description

The product includes a client that computes a hash of a password and sends the hash to another component, which compares the supplied hash to the hash obtained from a data store of password hashes.

## Modes Of Introduction

- **Implementation**: REALIZATION: This weakness is caused during implementation of an architectural security tactic.
- **Architecture and Design**: Some authentication mechanisms rely on the client to generate the hash for a password, possibly to reduce load on the server or avoid sending the password across the network.

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Access Control<br>Authentication | Bypass Protection Mechanism<br>Gain Privileges or Assume Identity | An attacker could bypass the authentication routine without knowing the original password. The attacker could obtain a copy of the hash (e.g., through a separate weakness against a database of authentication credentials), then use a modified client to replay the stolen hash. As a result, the server-side comparison against a client-side hash does not provide any more security than the use of passwords without hashing. |
