# CWE-600: Uncaught Exception in Servlet

## Description

The Servlet does not catch all exceptions.

## Alternate Terms

- **Missing Catch Block**

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Confidentiality<br>Availability | Read Application Data<br>DoS: Crash, Exit, or Restart | When a Servlet throws an exception, the default error response the Servlet container sends back to the user typically includes debugging information. This information is of great value to an attacker. For example, a stack trace might show the attacker a malformed SQL query string, the type of database being used, and the version of the application container. This information enables the attacker to target known vulnerabilities in these components. |

## Potential Mitigations

- **Phase:** Implementation

  Implement Exception blocks to handle all types of Exceptions.

## Demonstrative Examples

### Example 1 (DX-39)

The following example attempts to resolve a hostname.

*Example (Bad, Java):*

```java
protected void doPost (HttpServletRequest req, HttpServletResponse res) throws IOException {
    String ip = req.getRemoteAddr();
    InetAddress addr = InetAddress.getByName(ip);
    ...
    out.println("hello " + addr.getHostName());
}
```

A DNS lookup failure will cause the Servlet to throw an exception.
