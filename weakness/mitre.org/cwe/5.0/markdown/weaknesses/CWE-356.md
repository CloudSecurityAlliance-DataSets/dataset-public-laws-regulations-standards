# CWE-356: Missing User Interaction for Potentially Unsafe Action

## Description

The product encounters a situation in which some of its behavior is security-critical and should be authorized by a human before progressing, but it does not properly consult with the human user or its proxy (such as UI approval dialogues or pre-set policies) to determine whether it is allowed to perform the potentially dangerous behavior.

## Alternate Terms

- **Human-in-the-Loop**: Used in various applications, especially for AI/ML applications, to indicate situations in which the human user must be consulted before determining the next action to take.
- **HITL** (Acronym): Acronym for "Human-in-the-Loop"

## Modes Of Introduction

- **Architecture and Design**: The architecture or design might include a component or potentially dangerous functionality that could effectively act independently.
- **Implementation**: A bug in the implementation could cause the product to fail to recognize that it is about to perform a dangerous operation requiring a human decision.

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Non-Repudiation | Hide Activities | This makes it easier for attackers to trick users into inflicting damage to their system. |

## Potential Mitigations

- **Phase:** Architecture and Design

  Product systems should warn users that a potentially dangerous action may occur if the user proceeds. For example, if the user downloads a file from an unknown source and attempts to execute the file on their machine, then the application's GUI can indicate that the file is unsafe.
