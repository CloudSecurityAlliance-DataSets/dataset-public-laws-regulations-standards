# CWE-683: Function Call With Incorrect Order of Arguments

## Description

The product calls a function, procedure, or routine, but the caller specifies the arguments in an incorrect order.

## Modes Of Introduction

- **Implementation**: This problem typically occurs when the programmer makes a typo, or copy and paste errors. While this weakness might be caught by the compiler in some languages, it can occur more frequently in cases in which the called function accepts variable numbers or types of arguments, such as format strings in C. It also can occur in languages or environments that do not enforce strong typing.

## Detection Methods

- **Method:** Automated Analysis

  Because this function call often produces incorrect behavior, it will usually be detected during testing or normal operation of the product.

- **Method:** Automated Analysis

  Exercising all possible control paths will typically expose this weakness, except in rare cases when the incorrect function call accidentally produces the correct results, or if the provided argument type is very similar to the expected argument type.

## Potential Mitigations

- **Phase:** Implementation

  Use the function, procedure, or routine as specified.

## Demonstrative Examples

### Example 1 (DX-62)

The following PHP method authenticates a user given a username/password combination but is called with the parameters in reverse order.

*Example (Bad, PHP):*

```php
function authenticate($username, $password) {
    // authenticate user
    ...
}

authenticate($_POST['password'], $_POST['username']);
```
