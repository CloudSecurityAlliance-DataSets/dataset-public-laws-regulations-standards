# CWE-591: Sensitive Data Storage in Improperly Locked Memory

## Description

The product stores sensitive data in memory that is not locked, or that has been incorrectly locked.

## Background Details

On Windows systems, the VirtualLock function can lock a page of memory to ensure that it will remain present in memory and not be swapped to disk. However, on older versions of Windows, such as 95, 98, or Me, the VirtualLock() function is only a stub and provides no protection. On POSIX systems, the mlock() call ensures that a page will stay resident in memory but does not guarantee that the page will not appear in the swap. Some platforms, in particular Linux, do make the guarantee that the page will not be swapped, but this is non-standard and is not portable. Calls to mlock() also require supervisor privilege.

## Modes Of Introduction

- **Implementation**: The developer might use functions such as VirtualLock() or mlock(). On some systems, this does not guarantee that the page will not appear in the swap. See Background Details.

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Confidentiality | Read Application Data<br>Read Memory | The memory, including sensitive data, might be written to swap files on disk by the virtual memory manager, possibly making the data more accessible to adversaries. |

## Potential Mitigations

- **Phase:** Architecture and Design

  Identify data that needs to be protected from swapping and choose platform-appropriate protection mechanisms.

- **Phase:** Implementation

  When using potentially risky functions such as mlock() or VirtualLock(), check return values to ensure that locking operations are successful.
