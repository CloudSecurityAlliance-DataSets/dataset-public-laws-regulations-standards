# CWE-910: Use of Expired File Descriptor

## Description

The product uses or accesses a file descriptor after it has been closed.

## Alternate Terms

- **Stale file descriptor**

## Background Details

After a file descriptor for a particular file or device has been released, it can be reused.

## Modes Of Introduction

- **Implementation**

## Likelihood Of Exploit

Medium

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Confidentiality<br>Integrity | Read Files or Directories<br>Modify Files or Directories | The reused file descriptor might reference a different file or device than the original file descriptor. As a result, the program could read data from, or write data to, the wrong file. |
| Availability | DoS: Crash, Exit, or Restart | Accessing a file descriptor that has been closed can cause a crash. |

## Detection Methods

- **Method:** Automated Static Analysis · **ID:** DM-14

  Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

  **Effectiveness:** High
