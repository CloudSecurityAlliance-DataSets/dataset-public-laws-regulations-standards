# CWE-354: Improper Validation of Integrity Check Value

## Description

The product does not validate or incorrectly validates the integrity check values or "checksums" of a message.

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Integrity<br>Other | Modify Application Data<br>Other | Integrity checks usually use a secret key that helps authenticate the data origin. Skipping integrity checking generally opens up the possibility that new data from an invalid source can be injected. |
| Integrity<br>Other | Other | Data that is parsed and used may be corrupted. |
| Non-Repudiation<br>Other | Hide Activities<br>Other | Without a checksum check, it is impossible to determine if any changes have been made to the data after it was sent. |

## Detection Methods

- **Method:** Automated Static Analysis · **ID:** DM-14

  Automated static analysis, commonly referred to as Static Application Security Testing (SAST), can find some instances of this weakness by analyzing source code (or binary/compiled code) without having to execute it. Typically, this is done by building a model of data flow and control flow, then searching for potentially-vulnerable patterns that connect "sources" (origins of input) with "sinks" (destinations where the data interacts with external components, a lower layer such as the OS, etc.)

## Potential Mitigations

- **Phase:** Implementation

  The protocol specification describes the algorithm used for calculating the checksum. It is then a matter of implementing the calculation and verifying that the calculated checksum and the received checksum match.
