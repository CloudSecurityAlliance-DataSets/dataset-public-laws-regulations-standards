# CWE-1471: Insufficiently Controlled Parser Differential

## Description

The product uses a common specification or format that is shared between multiple components or entities, but the components have different parsers that can interpret the same input in different, security-relevant ways.

## Modes Of Introduction

- **Requirements**:

  The product's components might be required to follow a specification that is incomplete in ways that do not sufficiently cover security expectations, and/or allows for implementation-specific variations that may be security-critical.

  (All Phases: Requirements, Architecture and Design)

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Integrity<br>Authorization<br>Access Control | Gain Privileges or Assume Identity<br>Bypass Protection Mechanism<br>Hide Activities<br>Alter Execution Logic<br>Unexpected State<br>Varies by Context | If an input is analyzed and/or processed by multiple components in security-related situations - such as analyzing headers or comparing identifiers - then a parser differential could lead to incorrect security decisions. |

## Detection Methods

- **Method:** Automated Dynamic Analysis

  The different product components or entities could be tested using inputs with a variety of manipulations, such as differences in capitalization, whitespace, "boundary" tags, etc. The behavior of each component could be evaluated to see if the inputs are handled consistently.

## Potential Mitigations

- **Phase:** Architecture and Design; Implementation

  If possible, ensure that the same parser is used by each component.

  **Effectiveness:** High

  **Effectiveness Notes:** This might be difficult to do if the affected product has some components or entities that are not directly under its control, such as with firewalls managing traffic between diverse systems that might have a variety of libraries across different operating systems, programming languages, etc.
