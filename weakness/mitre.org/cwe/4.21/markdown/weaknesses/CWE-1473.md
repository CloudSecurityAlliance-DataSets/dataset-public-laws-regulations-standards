# CWE-1473: Improper Expiration of Cached Data

## Description

The product uses or supports data in a cache, but it does not properly specify an expiration with a date, time, or time period that is sufficient for the intended security policy of the product or its adminstrators.

## Modes Of Introduction

- **Implementation**: Developers might inadvertently omit specifying a specific expiration for the data. With some cache mechanisms, this could cause the data to be labeled as having no expiration at all.

## Common Consequences

| Scope | Impact | Note |
| --- | --- | --- |
| Access Control<br>Integrity<br>Other | Gain Privileges or Assume Identity<br>Bypass Protection Mechanism<br>Unexpected State<br>Varies by Context | If the cached data is used for security-critical functionality such as authentication, authorization, or identity, then this might allow users or adversaries to perform operations beyond their expected lifetime. If the data is old but used for identification, such as DNS lookup results, then the stale data could point to entities that are no longer controlled by the intended owner. |

## Potential Mitigations

- **Phase:** Architecture and Design; Implementation

  For each type of cached data, determine the best lifetime that balances efficiency provided by the cache with the security implications of the data becoming too stale. Explicitly specify an expiration date or time period.

## Demonstrative Examples

### Example 1

Some JVM implementations cache DNS resolution results by default.

*Example (Bad, Algorithm):*

```algorithm
The expiry setting of the cached results might either
be inappropriately long for the program or set to
never expire.
```

This results in a situation where changes to DNS records seemingly do not take effect in the program. This could cause the product to communicate with IP addresses that are no longer associated with the updated DNS records.

*Example (Good, Algorithm):*

```algorithm
To mitigate this situation, the DNS cache
setting networkaddress.cache.ttl for the JVM needs to
be set appropriately.
```
