## Upstream

Mappings live under `mappings/<target>/attack-<version>/`, and **prior versions are retained** — you can fetch the mapping against an old ATT&CK release, not just the current one. A `legacy/` directory holds older artifact shapes.

Targets published upstream: `aws`, `azure`, `cri_profile`, `csa_ccm`, `gcp`, `intel-vpro`, `kev`, `m365`, `nist_800_53`, `veris`.

Note `csa_ccm` — CTID publishes an ATT&CK ↔ CSA Cloud Controls Matrix mapping, which is directly relevant to this organisation's own framework and is **not** currently tracked in this repository.

## Getting the data

```bash
# Browse what's available for a target
gh api repos/center-for-threat-informed-defense/mappings-explorer/contents/mappings/nist_800_53 --jq '.[].name'

# Fetch a specific mapping (paths vary slightly per target — list the directory first)
gh api repos/center-for-threat-informed-defense/mappings-explorer/contents/mappings/gcp/attack-19.1 --jq '.[].name'
```

## What's in this directory

Metadata stubs pointing upstream, per the [no-bulk-mirror rule](../../../CLAUDE.md#dont-bulk-mirror-data-thats-already-publicly-available-upstream) — with **one deliberate exception**.

On 2026-08-14, 42 committed files (~6.3 MB) were removed from `AWS/`, `azure/`, `gcp/`, `m365/`, `nist_800_53/` and `veris/`. Each of those directories already declared `desired_end_state: metadata-only / upstream-only` in its own metadata while holding the data anyway. The snapshots mapped ATT&CK **8.2 through 14.1** against a current **19.2**, and upstream retains every version we held plus newer ones — so nothing was lost. Files remain in git history and in S3.

`m365/` also held 35 per-capability split files generated by `split-file.py` from the consolidated mapping. Those were removed too: the script is retained and regenerates them in one run, so the outputs were reproducible rather than irreplaceable.

### The exception: `cve/`

`cve/cve-10.21.2021_attack-9.0-enterprise.json` is **retained**, because the reasoning that justified removing the others does not hold for it:

- Upstream's `mappings/` directory has **no `cve` target**. It publishes aws, azure, cri_profile, csa_ccm, gcp, intel-vpro, kev, m365, nist_800_53 and veris — the built CVE mapping is not among them.
- What remains upstream is the source CSV (`src/mapex_convert/mappings/Att&ckToCveMappings.csv`) and a parser, not a published output.
- The original [`attack_to_cve`](https://github.com/center-for-threat-informed-defense/attack_to_cve) project is **archived** (last push 2024-04-03).

Removing it would have discarded the only readily available copy of a built artifact upstream no longer ships. That is the case the no-bulk-mirror rule is not aimed at.

## Relationship to sibling frameworks

- **[ATT&CK](../../../ttp/mitre.org/attack/)** — every CTID mapping is anchored to a specific ATT&CK version, named in its directory path.
- **CSA CCM** (`control/cloudsecurityalliance.org/ccm/`) — upstream publishes a `csa_ccm` mapping not currently tracked here.
