## Legend

| Term | Meaning |
|---|---|
| `unchanged` | Same identifier, same title, byte-identical specification |
| `renumbered` | Same control, different identifier |
| `retitled` | Same control, different title |
| `specification rewritten` | Requirement text changed materially (similarity < 0.95) |
| `specification edited (cosmetic)` | Whitespace, typo, or boilerplate-clause change only |
| `ADDED` | New control with no predecessor |
| `REMOVED` | Control with no successor — the requirement is gone |
| **⚠ ID REUSE** | This identifier designated a *different* control in the old release |

## What CSA's change log says

The `Change Log` worksheet in the v1.1.0 workbook describes the release as
**five new controls** (`DCS-01`, `DCS-17`, `DCS-18`, `LOG-08`, `SEF-09`) and
**one deletion** (`IAM-12`). Those are all corroborated here.

What it does not mention:

- **53 controls were renumbered.** Not referenced anywhere in the change log.
- **54 identifiers now designate a different control.** The direct consequence of the above.
- **34 specifications were rewritten**, six of them under an unchanged ID *and* title.
- **`SEF-09` *Incident Response* was removed**, while the identifier `SEF-09` was
  simultaneously reused for a new control, *Incident Records Management*. The change
  log lists `SEF-09` as an addition without noting the removal or the reuse. The
  dropped requirement — define incident categories and severity levels for AI systems,
  including automated response — has no successor in 1.1.0, yet the new `SEF-07`
  refers to "incident categories and severity levels" as though something still
  establishes them.
- **`SEF-04` was weakened** from *"Follow a structured approach to evaluate the
  effectiveness of incident response plans"* to *"Exercise the incident response plans"*.

Treat the CSA change log as a statement of intent. This file is the delta.
